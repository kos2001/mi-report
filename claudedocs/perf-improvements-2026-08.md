# 성능 개선 (2026-08-03)

2026-07 개선(병렬화·이벤트 루프 보호·커넥션 재사용) 이후 남은 병목을 측정으로 찾아
제거했다. 이번 라운드의 지배 요인은 **원격 임베딩 왕복 횟수**(bge-m3, 실측 300~500ms/회)와
**코퍼스 크기에 선형인 벡터 로드**였다. 백엔드 테스트 284개 통과, ruff 클린,
프론트엔드 tsc/eslint 클린, uvicorn 실 스모크(뉴스 수집·RAG 검색·문서 상세) 검증.

## 적용 내역

### 1. 임베딩 왕복 횟수 줄이기 (지배 요인)
- `collection.add_crawled_documents` 신설 — 커넥터(Confluence/한경/URL)가 문서마다
  임베딩 왕복 + 쓰기 트랜잭션을 반복하던 것을 **배치 임베딩 1회 + 트랜잭션 1회**로.
  Confluence 기본 동기화(25페이지)면 왕복 25회 → 1회.
  `add_crawled_document` 는 단일 항목 래퍼로 남겨 기존 호출부 계약을 유지한다.
- `collection.hybrid_search_multi` / `documents_for_rag_multi` 신설 — 여러 질의를
  임베딩 배치 1회·벡터 로드 1회로 검색하고, 겹친 문서 본문은 한 번만 읽는다.
  `agentchat.ground_answer`(질문·답변 2질의)가 이 경로를 쓴다. `hybrid_search` 는
  단일 질의 래퍼이고 BM25 폴백 규약은 그대로다.

### 2. 문서 벡터 행렬 캐시 (코퍼스 크기 대응)
2026-07 에 "코퍼스가 커지면 재검토"로 남겨 둔 항목. 질의마다 전체 임베딩을 DB 에서
읽어 numpy 행렬로 만드는 비용이 코퍼스에 선형(20k 문서·1024차원에서 46ms)이었다.
- L2 정규화까지 미리 해 프로세스 캐시 → 질의당 비용은 행렬-벡터 곱 1회.
  스레드마다 80MB 를 임시 할당하던 이전 동작보다 메모리도 유리하다.
- 무효화: DB `cache_version` 행(쓰기 트랜잭션에서 함께 증가 → 다른 프로세스의 쓰기도
  감지) + `MAX(rowid)` 예비 감지. **임베딩 행 수(COUNT(*))를 키로 쓰면 4KB 블롭
  페이지를 전부 훑어 캐시보다 비싸다**(측정으로 확인 — 첫 구현을 되돌린 지점).
  회귀 가드: 삭제·신규 적재·"마지막 행 삭제 후 삽입"(행 수·rowid 가 되돌아오는 경우)
  세 케이스 테스트.
- dense 순위는 전체 argsort 대신 `argpartition` 으로 상위 pool 만 만든다.

### 3. 불필요한 I/O 제거
- `_read_path_text(max_chars=N)` 가 파일 전체를 읽고 잘라내던 것을 앞부분만 읽도록.
  인제스트 문서는 수 MB 까지 커지는데 LLM 컨텍스트엔 앞 4천 자만 쓴다.
  strict 디코딩을 유지해 바이너리 업로드는 계속 None(잘린 경계 오류만 절단 처리).
- `profiles.load_profile` — 요청마다(`get_client`, `/agent/chat` 등) 반복하던
  .env 읽기 + config.yaml YAML 파싱(약 0.5ms, 이벤트 루프 블로킹)을 (mtime_ns, size)
  키 캐시로 제거. os.environ 적용은 매번 수행해 '이미 있는 값 보존' 규약을 유지한다.

### 4. 프론트엔드
- 다중 파일 업로드를 순차 → 동시 4건(`UPLOAD_CONCURRENCY`). 개별 실패는 나머지를
  막지 않는다. 백엔드 업로드는 스트리밍 저장 + 워커 스레드 등록이라 동시 요청에 안전
  (실측: 8건 동시 업로드에서 잠금 오류 없음).

## 검토했지만 적용하지 않은 것
- **BM25(FTS5 OR 매칭) 최적화** — 이제 로컬 비용의 대부분이다(문서 20k 합성 코퍼스에서
  61ms). 원인은 OR 질의가 18,805건을 매칭해 전부 bm25 스코어링하는 것.
  AND 우선 → 부족하면 OR 폴백으로 바꾸면 1.5ms 로 떨어지지만 회수율(recall) 설계를
  바꾸는 일이라 보류. 실 코퍼스는 합성 코퍼스만큼 매칭이 조밀하지 않다.
- **grounding 수치 검증** — 측정 결과 병목이 아니다(문서 180KB 기준 strict 0.55ms,
  가수 폴백 4.6ms).
- **ANN 인덱스(sqlite-vec/faiss)** — 벡터 캐시는 문서 10만 건·1024차원에서 약 400MB.
  그 규모에서는 전수 dense 계산 대신 ANN 으로 넘어가는 것이 다음 레버다.
- **uvicorn 다중 워커** — 2026-07 판단 유지(임베딩/모델 메모리 중복).
